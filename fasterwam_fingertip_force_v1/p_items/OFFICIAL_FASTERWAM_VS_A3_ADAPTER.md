# 官方 FasterWAM vs A3 当前执行接口（源码级对照）

## 已由源码证实（高置信）
| 环节 | 官方 FasterWAM (LIBERO) | 我们 A3 当前 (F0/F2) |
|---|---|---|
| 训练 | 连续 Flow-Matching 动作 MSE（非夹爪分类网络） | 同：连续 FM 速度场 MSE，7 维等权（`fastwam.py:850`） |
| 夹爪标签 | 连续回归 | V3 连续原始开度（0.28/0.49/1.0），非 pm1 |
| 评估解码 | **可选 `binarize_gripper`：`action[...,-1]=sign(...)`** | **连续**：`g=2a−1`（不二值化） |
| 执行器语义 | 仿真按 sign 开/合 | env：`target opening=(g+1)/2`（`sim/actions.py:149`） |
| 复合结果 | sign → 开度∈{0,0.5,1} | `(2a−1+1)/2 = a` → **精确等于模型输出开度** |

## 关键推论（当前半开 0.43 下两种执行器的后果）
- **连续（现状）**：目标开度 0.43 → 夹爪只到 0.43 → 对约 0.28 厚的饼干合不拢 → 抓不住。
- **官方 sign 二值**：a=0.43→g=−0.14→sign −1→开度 0（完全闭合）→ **能夹住**；但 a=0.49(释放)→g=−0.02→sign −1→**也闭**→**无法释放**。
- ⇒ **两种执行器都使 exact_fill=0，但失败点不同（连续=抓不住；二值=放不开）**。执行器不是免费修复；根因仍是**模型输出停在 mid-band ~0.43**（H2）+ 是否**自主到达抓取态**（H3）。

## 结论：方向没偏，但漏了"执行器语义"这一维
- V3（连续标签+连续执行）是**忠于专家**的路线；但**未对齐官方"评估期二值化"这一执行选择**。
- **0.28 不是通用抓取判据**（取决于饼干厚度/数量）；验收应用**力+任务结果**，不用开度阈值。
- 旧 `bridge/action_adapter*.py`（另一 agent 引用）在本仓 `main`/`a3-cookie-r27` **未被跟踪**（`git ls-tree` 无此文件）→ 本地无法 git-diff；标 **NOT_FOUND_LOCAL**，需远端/其他克隆核对。

## 无训练、最高价值下一步：三执行器对照（同场景同 seed）
在 F0 15k / F2 15k 上，同一 rollout 分别用：
1. **CONT**：连续开度（现状）
2. **BIN_SIGN**：官方 sign 二值
3. **BIN_DATA**：按数据自然阈值（a≤0.35 闭 / a≥0.80 开 / 其余保持上一步），**不用 0.5 魔法阈值**
测：抓取(接触+提起)、稳定提起/携带、**释放成功**、strict/relaxed 入盒、exact_fill。→ 直接判定"mid-band 是否为致命"及"哪种执行器语义最贴合物理任务"。**仅评估、0 优化步、串行在 f0 r-sweep 之后**。
