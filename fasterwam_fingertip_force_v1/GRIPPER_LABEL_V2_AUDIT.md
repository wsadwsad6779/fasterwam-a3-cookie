# GRIPPER_LABEL_V2_AUDIT（原始 100 条语料，2026-11-23）

数据：`archive_evidence/data/a3_fw/arrays.npz`（100 episodes / 42,681 帧；action 7D、opening、joint_cmd）。
方法：以专家 `joint_cmd − opening` 的符号（死区 0.02）定义“闭合意图/张开意图”；阶段按事件切分：
接近 = 首次抓取前；抓取 = 首次闭合意图且 5 帧后 opening<0.6；携带 = 抓取后到释放前且 opening<0.6；
释放 = 抓取后首次张开意图且 5 帧后 opening 上升 >0.05。

| 指标 | 值 |
|---|---|
| 抓取事件 | 100（每回合 1 次） |
| 释放事件 | 100 |
| 接近段物理张开帧（opening>0.8） | 425 |
| 其中被原标签标为“闭合(+1)” | 48.0%（204/425） |
| 携带段帧（opening<0.6） | 20,820 |
| 其中被原标签标为“闭合(+1)” | **61.5%（12,801 / 20,820）** |
| 释放事件被标为“张开(−1)” | 100%（100/100） |
| 原标签翻转总数 | 1,892 |
| 单帧开合脉冲 | 318 |

## 结论（两类缺陷都成立）
1. **微抖动翻转**：携带段 38.5% 的帧被标成“张开”，1 帧脉冲 318 个——来自 `sign(opening[t+1]−opening[t])` 对接触引起的 opening 抖动敏感。
2. **保持张开被继承为闭合**：接近段 48% 的物理张开帧标为 +1——来自“保持前一标签”的初始化（prev=+1）与死区规则。
3. 后续 97.5% 全闭修复只消除了 (1) 的可见抖动，却把 (2) 放大成多数类坍缩；V2 必须同时满足：
   - 接近段物理张开 → 必须 −1；
   - 携带段稳定夹持 → 必须 +1；
   - 释放 → −1，且释放后保持 −1；
   - 禁止 1 帧脉冲与死区内的来回翻转。

## V2 规则（候选，待逐事件验收）
以专家 `joint_cmd` 为指令真值（它是目标开度，不依赖 opening 噪声）：
- `err = joint_cmd − opening`；`err < −ε` → 闭合(+1)；`err > +ε` → 张开(−1)；
- 死区内**不继承**，而是按物理状态判定：`opening ≥ 0.8` → −1；`opening ≤ 0.6` → +1；
- 最小持续时间 5 帧；合并 1 帧脉冲；释放后至少保持张开 5 帧。

验收（必须在事件级验证集上，不用总体符号一致率）：
接近段张开准确率、携带段闭合保持率、释放召回率与时间偏差、脉冲数、翻转数、各类窗口占比。
